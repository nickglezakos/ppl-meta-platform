EVALUATION LOGIC
================

Given demographic data:
{
  people_count: 15,
  percent_male: 65,
  percent_female: 35,
  percent_age_18_24: 40,
  ...
}

Trigger conditions:
[
  {field: "people_count", operator: "gt", value: 10},
  {field: "percent_age_18_24", operator: "gte", value: 30}
]

Evaluation:
1. people_count (15) > 10? ✅ YES
2. percent_age_18_24 (40) >= 30? ✅ YES

Result: ✅ TRIGGER PASSES (all conditions met)

Action: Execute linked user action (digital_signage)


KEY IMPROVEMENTS
================

Before:
- Overlapping fields (person_count_threshold vs demographic_conditions)
- Signage config mixed in trigger model
- Hard to add new condition types
- Confusing UI with multiple condition sections

After:
- Single unified condition format
- Signage config in separate action
- Easy to add new fields/operators
- Clean UI with dynamic condition builder
- Better separation of concerns
- Type-safe validation
