03

Scalable scenes — part A

≈ 20–25 minutes total. Scenes 0–3 build from the island site through live vision, identity, and automation.

0 Island site

≈ 2 min

Open the UI from the mobile router IP. Show cameras, signage, and presence devices online on the mobile-router LAN.

Point: Full EyeNet site, offline-capable, remotely reachable. No cloud video.

1 Live vision

≈ 3 min · Gate / Cameras / Instant Detection

Walk past Tapo A and the embedded camera. Show live feed + instant detection (faces / people / demographics). Optionally pan the mobile camera so they see “phone = camera too.”

Point: Any camera type becomes a sensor.

2 Known people

≈ 3 min · Individual Groups + ppl_match

Open Individual Groups (Staff / VIP / Visitors — whatever is already enrolled). Ensure 1–2 people in the room are group members. Walk past Tapo A as a known person → show match in Automation / last match info.

Point: Automatic person recognition.

3 Automation that already exists

≈ 4 min · Vradar / Triggers & Actions

Fire what is already configured — do not rebuild live. Recommended pair with multiple actions on the same trigger:

  • Known match → alert and/or signage_rich_message (“Welcome {matched_member_name}”) + email + Slack (messaging_app)
  • Negated match (unknown) → alert + visitor playlist / warning on signage + email + Slack (@channel if needed)

Have a second person (or briefly cover a face) walk as “unknown.” Open the email inbox and Slack channel so they see notifications arrive live.

Point: Vradar = vision → business action on screen, email, and Slack together. This is usually the “aha.”
04

Scalable scenes — part B

Scenes 4–6 close with the business view / benefits: signage, presence check-in, movable coverage. Scene 7 is optional.

4 Signage as business view / benefits

≈ 3 min · Signage + Automation

Stay on the Android player. Show default playlist → trigger switches playlist or rich overlay (welcome / visitor / promo). Optionally a demographic trigger (e.g. people_count ≥ 2 → promo playlist).

Point: Signage is not a plain screen system — it changes automatically from EyeNet rules.

5 Presence check-in

≈ 4 min · Presence

Use the Presence app + door camera (Tapo A or embedded):

  • QR-only grant (fast)
  • Then QR + face or camera match (higher assurance)

Show session result + recent presence grants.

Point: Attendance / door control with an audit trail — not just a face alert.

6 Same rules, movable camera

≈ 2 min · Mobile camera

Move the mobile camera to a second spot (“stock room”). Show the same style of trigger can apply there — or that search / multi-camera coverage is the natural next step.

Point: Coverage follows the site; not locked to fixed IP cams.

7 Close the loop Optional

≈ 2 min · Ops + VPN · only if requested

Optional — only if the customer asks. In UI: trigger execution log, presence sessions, optional analytics glance (traffic / demographics at Entrance). Reminder: you manage the site over Tailscale while it sits on a travel router.

Point: Ops + privacy + remote support without sending video to the cloud.

Practical tips for this kit

One scenario only

First demos: secured entrance with adaptive screen + staff check-in. Demographic retail can be Scene 4b — not a second scenario.

Pre-stage playlists & channels

Welcome / Visitor / Crowd-promo ready before the room fills. Open the email inbox and Slack channel before Scene 3 so notifications show live.

Cooldown

Keep trigger cooldown short (15–30s) during demos so walks re-fire cleanly.

Don’t live-edit

Groups and triggers are already active. Use them. Edit only if the buyer asks to see configuration.

Tailscale last

Prove local value, then show remote reach as the close of the presentation.

Skip on v1

Sentinel / Matrix / left-object / plates wait for a second meeting unless the buyer is security or multi-site.

08

Presence: stats, filters, PPP & HubSpot

Show that presence is more than check-in — it has reports, filters, and identity linkage through to the CRM.

A Presence Analytics & filters

Presence → Analytics · Sessions

Open Presence → Analytics:

  • Date range, summary cards, Outcomes / Client Origin donuts
  • User-Day Presence Awards — filter by user and date; expand for that day’s grants (QR / Cam / Cam & QR)
  • Bars for Session Modes, Grant Types, Failure Reasons, Policy Sources

Then Presence → Sessions: User filter, dates, and Filter sheet (Mode, Decision, Grant, Policy, Failure, Origin, Camera, Group, Member, Profile). Show Apply / Clear and optionally Download Excel.

Point: One tap on a card/donut/bar → Sessions with the same filters. Audit trail for HR and security.

B Linking group members · PPP · Users

Individual Groups · Presence → People

Show the identity chain:

  • Group member (Individual Groups) — the person Vradar / Presence match recognizes
  • PPP (Presence People Profile) — presence profile (name, email, phone…) linked to the group member
  • User — platform / Authenticator account that can link to the same PPP

In Individual Groups: link icon on a member → select / link People Profile. In Presence → People: open the PPP and show linked fields.

Point: One person = one identity from recognition through check-in to the user account.

C HubSpot CRM link

Presence → Settings → HubSpot CRM

Open Settings → HubSpot CRM (if already connected on the demo):

  • Import HubSpot contacts → create / update PPP (External Ref = HubSpot contact id)
  • After a Presence grant → post to HubSpot (Note on the contact + last_presence_* properties)
  • Choose which grant types to post (check_in, presence_match, verified_presence)

If live connection exists: run a grant and open the contact in HubSpot. If not: show the settings screen and explain the flow.

Point: Presence reaches the CRM without manual logging — HubSpot-first connector.
09

General Analytics (MVR)

Home → Analytics: overall picture of traffic, demographics, and behaviour — not just one door event.
Where you go

Open Analytics (MVR People Detection Analytics). Tap Filters: time (e.g. Today), collection / camera (e.g. Entrance Tapo), data source.

Data sources

Instant Detection (live), Video Recording, or both (combined) with identity de-duplication.

1 Level 1

Basics: Total People, Active Collections, Sessions / Videos Analyzed.

2 Level 2

Time trends: Total, Peak, Average — hourly / daily traffic.

3 Level 3

Demographics: age, gender, per camera.

4 Level 4

Behavioral: peak hours, visit frequency, weekly heatmap.

5 Filters

Apply → filter bar appears. Refresh for new data.

6 Export

Optionally Export Analytics (e.g. Excel) for the buyer.

Point: From the same kit (Tapo A/B + instant detection) you get an operational dashboard for entrance, hours, and audience — without a separate BI tool.
10

MVR People Analysis: Routes, Attendance & Search Videos

Show how you reach person analysis from Search / Media and what you see on Routes and Attendance.

1 How you get there — Search Videos / Media

Entry paths into the analysis screen

  • My Media / Media Preview — open a camera clip → Details (after processing) → person / MVR analysis screen
  • Search Videos (or date/time MVR search on the collection) → select results → Analysis
  • Individual Groups — Camera Search or tap a group member → Person Objects / cross-video analysis
Point: From video search or a known group member you reach the same family of analysis screens.

2 MVR People Analysis screen features

Tabs on Details / Person analysis

  • Persons / Individuals — who appeared in the video (or across videos)
  • Face Details — individual face detections when you need depth
  • Routes — movement path in the frame (Camera View + Top View · Path or Scatter); dwell / door crossing
  • Attendance (cross-video) — who appeared when + timeline per camera in the analysis window

Note: Attendance here is appearance analysis on the selected videos — related to but different from Presence grants (section 08).

Point: Not only “who” — also “where they moved” and “when they appeared” in the search window.

3 Demo beat on this kit

≈ 3–4 min if requested

  1. Make a short recording or open a recent clip from Tapo A / embedded
  2. Search Videos or Media Preview → Details
  3. Show Persons → Routes → (if multi-video) Attendance
  4. Optional: open the same analysis from an Individual Group member
Point: Forensics and operational review without video leaving the site.
