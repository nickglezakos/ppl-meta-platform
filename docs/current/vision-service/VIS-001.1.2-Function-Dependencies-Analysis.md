### 3.2 Connection Management Patterns

**Pattern 1**: Context Manager (Recommended)
```python
with Face(logger) as face:
    cursor = face.db_connection()
    # Operations
```
- **Used in**: `face_detector.py`, `video_processing.py`
- **Advantages**: Automatic cleanup, transaction management

**Pattern 2**: Manual Connection Management
```python
self.conn = sqlite3.connect(db_file)
# Manual operations and cleanup
```
- **Used in**: `face_processor.py`, `face_comparer.py`
- **Risk**: Resource leaks, transaction issues

**Pattern 3**: API-Level Connections
```python
conn = sqlite3.connect(db_path)
cursor = conn.cursor()
# Operations
cursor.close()
conn.close()
```
- **Used in**: `api.py` (numerous instances)
- **Risk**: Inconsistent error handling

## 6. Data Flow Mapping Between Stages

### 6.1 Data Transformation Pipeline

```text
Raw Video → Frame Extraction → Face Detection → Face Grouping → 
Person Identification → Face Comparison → Person Prints → API Response
```

**Data Format Transformations**:

1. **Video → Frames**: MP4/AVI → JPEG files
2. **Frames → Face Detections**: JPEG → Bounding boxes (x,y,w,h)
3. **Detections → Groups**: Bounding boxes → Group tags
4. **Groups → Person IDs**: Group tags → Person tabs
5. **Person IDs → Embeddings**: Face crops → 512-dim vectors
6. **Embeddings → Similarities**: Vectors → Float scores (0-1)

## 7. Database Schema Dependencies Documentation

### 7.1 Vision-Related Database Schema

```sql
-- Core detection data
CREATE TABLE RawDetectionData (
    Id INTEGER PRIMARY KEY,
    frame BLOB,
    timestamp REAL,
    frame_path TEXT
);

-- Face detection results
CREATE TABLE FaceRects (
    Id INTEGER PRIMARY KEY,
    RawDetectionDataId INTEGER,
    rect_x INTEGER,
    rect_y INTEGER,
    rect_width INTEGER,
    rect_height INTEGER,
    grouptags REAL,        -- Links to face grouping
    persontabs REAL,       -- Links to person identification
    FOREIGN KEY (RawDetectionDataId) REFERENCES RawDetectionData (Id)
);

-- Face image storage
CREATE TABLE FacePics (
    Id INTEGER PRIMARY KEY,
    RawDetectionDataId INTEGER,
    face_pic TEXT,
    FaceDetectionFilter INTEGER,
    age INTEGER,
    gender TEXT,
    FOREIGN KEY (RawDetectionDataId) REFERENCES RawDetectionData (Id)
);

-- Face unique identifiers
CREATE TABLE FaceUids (
    Id INTEGER PRIMARY KEY,
    RawDetectionDataId INTEGER,
    face_uid TEXT,
    age INTEGER,
    FOREIGN KEY (RawDetectionDataId) REFERENCES RawDetectionData (Id)
);

-- Face matching results
CREATE TABLE MatchedFaces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    uid1 TEXT NOT NULL,
    uid2 TEXT NOT NULL,
    grouplabel TEXT
);
```

### 7.2 Database Relationship Dependencies

**Foreign Key Relationships**:
- `FaceRects.RawDetectionDataId` → `RawDetectionData.Id`
- `FacePics.RawDetectionDataId` → `RawDetectionData.Id`
- `FaceUids.RawDetectionDataId` → `RawDetectionData.Id`

**Data Flow Dependencies**:
1. **Detection Phase**: `RawDetectionData` → `FaceRects` → `FacePics` → `FaceUids`
2. **Grouping Phase**: `FaceRects.grouptags` assignment
3. **Person ID Phase**: `FaceRects.persontabs` assignment
4. **Matching Phase**: `MatchedFaces` population

- **25+ function call sites** across module boundaries
- **6 database tables** with foreign key relationships

**Critical Success Factors** for extraction:
1. **Preserve database schema integrity** with proper foreign keys
2. **Maintain configuration consistency** across all modules
