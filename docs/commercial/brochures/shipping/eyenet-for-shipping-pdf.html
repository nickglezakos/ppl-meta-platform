About Eyenet for Shipping

Ships are isolated, safety-critical environments operating far from shore-based management. Eyenet brings computer vision-powered crew presence, restricted area protection, and automated multi-level notifications to every vessel — then connects the fleet through a secure VPN mesh.

The maritime industry faces operational challenges that off-the-shelf security systems cannot address. A vessel at sea is self-contained: crew must be accounted for, watch stations must stay manned, restricted zones must be enforced 24/7, and all of this must work with zero internet dependency. Each vessel runs a complete EyeNet installation on a single mini PC — fully offline at sea, synchronising with headquarters when docked or via satellite.

The Maritime Operational Challenge

Offline Core Operation

Ships operate without internet for days or weeks. Presence tracking, alerting, and access control must run locally. Data syncs when connectivity resumes.

Safety Critical Environment

Know who is onboard and where. Enforce restricted areas. Support lone-worker monitoring and muster headcount without manual roll calls.

Compliance Crew & Fleet Management

Bridge shore-side ERP crew modules with actual onboard presence. Detect mismatches and report to captain, officers, and HQ.

Eyenet Presence — Crew Attendance & Muster

Dual-factor crew verification at critical stations — facial recognition plus QR/NFC badge — with automated attendance reports to captain and HQ.

Presence assigns crew to watch schedules and zones, then tracks attendance in real time. Missed watch check-ins alert immediately — no delayed discovery of a missing person.

Maritime use cases

  • Watch changeover verification — dual-factor check-in at bridge and ECR; alert if the scheduled officer does not appear.
  • Muster station headcount — Area mode gives live accounted/missing status without manual roll calls.
  • ERP crew module sync — import schedules; export verified attendance when connected.
  • Certification-aware alerts — flag STCW gaps before a watch begins.
  • Automated reports — daily, per-voyage, and per-shift distribution to captain and fleet managers.

Automatic Notification Architecture

Three tiers: onboard alerts (zero latency), ship-to-HQ sync, and bi-directional ERP crew module integration.

1 Onboard

Zero latency. Local network only.

  • Watch absence → push + bridge alarm
  • Restricted zone → eyewear + captain
  • Muster headcount → captain / chief mate
  • Unrecognised gangway face → security + captain
  • Visitor still onboard at departure

2 Ship → HQ

VPN in port; satellite for critical alerts.

  • Daily attendance → fleet HR
  • Security events → CSO
  • Watch exceptions → fleet ops
  • Certification expiry → crewing
  • Queued sync when VPN returns

3 ERP Crew Module

Bi-directional shipping ERP sync.

  • ERP → manifest, schedules, certs
  • Eyenet → attendance & embark logs
  • Manifest mismatch alerts
  • Certification gap before watch
  • MLC rest-hour violation flags

Delivery channels

Captain Dashboard Officer Mobile Push Email to HQ Audible / Visual Alarm ERP Webhook Matrix Dashboard

Critical safety alerts (MOB, fire, abandon ship) notify all configured channels simultaneously.

Architecture properties

  • Mesh topology — vessels and HQ communicate directly; Matrix queries in parallel.
  • ACL fleet isolation — fleet tags prevent cross-fleet communication on the shared coordination server.
  • Zero public exposure — encrypted tunnels only; no public EyeNet service ports.
  • Automatic enrollment — pre-auth key from Authority; discoverable by Matrix after join.
  • Degraded resilience — offline vessels keep full local safety; Matrix marks them unreachable until sync.

Technical Specifications

1 Mini PC Per Vessel

16–32 GB RAM, modern multi-core CPU, standard GPU. Fanless form factor; 12–24V DC or 110–240V AC.

2–5 Cameras Per Vessel

Standard IP, WiFi, or USB cameras. Typical: gangway, bridge, ECR, muster, deck/cargo.

100% Offline Capable

Core safety and presence functions run fully offline. Connectivity affects HQ visibility only.

All applications run on-premises. Video and presence data never leave the vessel unless explicitly configured. The VPN mesh provides encrypted fleet connectivity without public exposure.
