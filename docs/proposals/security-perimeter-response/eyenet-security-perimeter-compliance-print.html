Executive Verdict

EyeNet fully complies as the AI detection, alarm, recording, and remote-command software layer for the requested perimeter. Physical towers, solar masts, loudspeakers, drone airframes/docks, ground radar, and radio/GPS hardware remain partner or site-supplied — EyeNet ingests their video and turns detections into verified alarms and response workflow.

Cost effectiveness is the governing constraint: the site rejected an aerostat. EyeNet avoids proprietary camera lock-in, runs on standard business hardware without mandatory GPU farms, and replaces wall-watching with alarm-led operations — so capital is spent on cameras and coverage where line of sight matters, not on passive video walls.

Software Compliant

Gate, Presence, Vradar, Sentinel, Matrix, Cameras/Vision, ONVIF connectors, Area & Drone modes cover intrusion, loitering, virtual perimeters, archives, and multi-workstation viewing.

Hybrid Partial — partner UAV

Drone mode and Vradar analyse aerial feeds and can cue or receive alarm launches via webhooks. Hybrid fuel, tethered, and drone-in-a-box hardware are not EyeNet SKUs.

BOM Site / partner

Tower PTZ/thermal optics, solar mobile towers, PA/sirens, LTE/mesh radios, UPS, lightning protection, radio dispatch, and vehicle AVL remain outside the EyeNet software licence.

Requested Operating Model

Care-and-maintenance mine: improve autonomous hybrid drone-based surveillance against intruders and theft — especially at night — then trigger a hands-on response team with a regular drone for close imaging and tracking.

Site constraints from the inbound brief

  • No fence — open access over rough terrain and heavy vegetation; boundaries are virtual.
  • ~7.44 km² site / ~12.12 km perimeter — wide-area detection required; static guard posts to be replaced in stages by mobile response to verified alarms.
  • Connectivity — cellular, local Wi‑Fi and Starlink at main central areas; not at perimeters.
  • Night priority — thermal + day/night optical detection for people and vehicles in dust and darkness.
  • Cost effectiveness — aerostat already rejected; start lean and expand from alarm heatmaps.

Local security wish-list (summary)

  1. Cameras on two existing towers (PTZ thermal + fixed AI)
  2. 4–6 solar mobile CCTV towers
  3. 1 drone-in-a-box + 1 tethered / overwatch drone
  4. Control-room upgrade to alarm-led VMS + GIS map + talk-down + resilience

How Each Application Serves the Perimeter

Gate + Area — fixed and mobile detection

Mount long-range PTZ and fixed wide-angle cameras on the two towers and on solar mobile towers. Gate covers approaches and access roads; Area covers pit edge, dumps, community boundary and artisanal hotspots. Instant detection feeds Vradar so operators receive person/vehicle alarms instead of empty footage.

Gate Area Compliant

Night & dust

Thermal + day/night optical streams are supported as standard camera sources. Analytics run on the normalised RTSP/ONVIF feed; sensor choice is a camera BOM decision, not a platform lock-in.

Presence — virtual fence where there is no fence

Define restricted zones for pit edge, dumps and community-facing boundary. Unauthorised presence triggers alerts. Staff and contractors can be enrolled so known presence does not flood the control room; unknown people and vehicles escalate.

Area Unauthorised presence

Vradar — alarm-led autonomy

Program parallel rules across all cameras: intrusion, loitering, after-hours movement, line-of-interest approaches. Actions include in-app alerts, email and webhooks that can cue a drone dock, dispatch console or response SOP. Same rules apply to aerial and wearable feeds.

Drone Goggles Webhooks

Drone mode + Goggles — verify then respond

When a tower or mobile unit raises a verified alarm, a docked or response UAV streams into Drone mode for close imaging and tracking. Response teams can use Goggles / Security Officer Agent for first-person collaboration with the control room — matching the brief’s “hands-on response including a regular drone.”

Hybrid fuel / tethered endurance

EyeNet is airframe-agnostic. Long nocturnal endurance (hybrid fuel, gasoline, tethered overwatch, or hot-swap electric units) is a drone OEM selection. EyeNet remains the AI and command layer for whichever feed arrives.

Sentinel — while static posts remain

As the site stages from static guard posts to mobile response, Sentinel keeps remaining posts accountable — inactive or empty posts escalate before they become blind spots.

Matrix + VPN — hub and backup office

Control room and security-office backup viewing share the same installation mesh. Starlink/cellular at the hub carries remote access; perimeter cameras use local radio/LTE backhaul into the on-prem node. Degraded mode continues to show reachable cameras if a link drops.

Recommended Cost-Effective Stack

Phased deployment aligned with the brief: start with towers and four mobile units, add cameras from alarm heatmaps, introduce drone autonomy when aviation approvals and OEM kit are ready.
  1. EyeNet node(s) in the control room — Gate + Area + Vradar + archives; optional second workstation / Matrix path for the security office backup viewing position.
  2. Cameras on the two existing towers first — thermal + optical PTZ where night and dust matter; fixed wide-angle AI cams on approaches and pit edge; tower-base camera for tamper.
  3. Start with four solar mobile AI towers — pit floor, dumps, remote tracks, community boundary; add up to two more from alarm data.
  4. One response UAV now (dock later) — feed Drone mode for close imaging; hybrid long-endurance or tethered overwatch via OEM when nocturnal flight time is proven necessary.
  5. Starlink / cellular at hub + radio / LTE at edges — EyeNet VPN for remote and backup viewing; no cloud dependency for video.
Phase 1 Detect

EyeNet + 2 tower packs + 4 mobile towers + control-room workstations. Replace wall-watching with alarm-led SOPs.

Phase 2 Respond

Response drone + webhook cueing; radio/AVL integration; talk-down PA on high-value towers.

Phase 3 Extend

Drone-in-a-box and/or tethered overwatch; optional ground radar slaved to PTZ; +1–2 mobile towers from heatmaps.

Bottom Line

EyeNet is the compliant software brain for unfenced mine-perimeter surveillance: virtual zones, AI intrusion and loitering alerts, drone and wearable response feeds, on-prem recording, and VPN backup viewing — without forcing cloud video or proprietary cameras.

Towers, solar masts, PA, radar, radio GPS, aviation approvals and hybrid/tethered airframes are partner BOM items that EyeNet consumes and drives into verified, alarm-led response. That split maximises coverage per dollar against the site’s stated cost constraint and rejected aerostat alternative.
