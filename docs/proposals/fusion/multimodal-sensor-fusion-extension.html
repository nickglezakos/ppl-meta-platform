Architecture Proposal

Multimodal Sensing & Sensor Fusion Extension

How to develop and embed non-camera sensor ingest and cross-modality fusion into the current EyeNet stack — without rewriting Cameras → Vision → VMeta — while reusing Media / Vradar actions.

Status Proposal
Date 11 Nov 2026
Author PPL Meta Platform Team

1. Executive Summary

EyeNet is camera- and computer-vision–centric today. It already supports within-vision multimodality (face ↔ body, objects/plates, multi-camera CV triggers) and limited Presence correlation (QR/NFC + camera). It does not yet ingest arbitrary physical sensors or fuse them with video under shared rules.

  1. Add a first-class Sensors domain (registry + ingest adapters + normalized events).
  2. Add a Fusion / Correlation layer joining sensors with camera / Instant Detection / Presence by time + place + rule.
  3. Reuse existing Media / Vradar actions (alert, email, webhook, signage, log).
  4. Expose via Gateway + Frontend as an Automation extension — not a parallel silo.
Design principle: treat video as one modality among many, while Cameras → Vision → VMeta remain authoritative for visual evidence.

2. Goals & Non-Goals

Goals

  • Pluggable ingest (HTTP first; MQTT / vendor APIs next)
  • Common SensorEvent envelope
  • Correlate with camera FOV / site topology + optional CV
  • Fire fused automations through Vradar actions
  • On-prem / VPN-first; no cloud dependency for core fusion
  • Make commercial fusion claims (thermal×optical, IoMT×vision) platform-capable

Non-goals (Phase 1–2)

  • Replacing cameras with a breaking polymorphic device table
  • Every vendor driver in v1
  • Deep ML late-fusion as the default
  • Raw high-rate waveform media as first-class storage
  • Hard coupling to a single partner stack

10. Reference Flows

Industrial threshold + camera

  1. Temp ≥ 70°C in Zone A
  2. Fusion requires camera evidence
  3. Instant Detection confirms context
  4. Webhook to BMS + in-app alert

Thermal × optical confirm

  1. Thermal alarm / thermal CV event
  2. Optical CV must also match in window
  3. AND → confirmed; else reject candidate
  4. False-alarm suppression with provenance

11. Recommendation

Proceed with a peer Sensors service and a Media-embedded Fusion engine that keeps the vision pipeline intact, reuses Vradar actions, and makes multimodal commercial claims implementable and auditable. Phase 0–2 delivers the platform spine; Phase 3+ monetizes vertical packs (fire confirm, industrial BMS, IoMT cooperation) on the same architecture.

Success bar: operator can create a fused rule in Automation UI; every fused alert carries modality provenance; existing Instant Detection / demographic / behavioural triggers remain regression-free.
