Overview

This guide covers installing the complete EyeNet PPL Meta Platform on a Windows 10 or 11 PC with an Intel or AMD processor. All services run inside Docker containers managed by Docker Desktop — no manual Python, PostgreSQL, or Node.js installations required.

The installation uses three files from the deployment/windows-installer/ directory. The PowerShell installer script automates the entire process: it creates configuration, pulls pre-built AMD64 Docker images from the public GitHub Container Registry, and starts all services.

Files You'll Need

Copy these three files from the project's deployment/windows-installer/ directory to a folder on the Windows machine (e.g. C:\EyeNet):

  1. install-platform.ps1 — PowerShell installer
  2. docker-compose.windows-installer.yml — Compose configuration
  3. .env.windows.template — Environment template

Prerequisites

Operating System Win 10/11

Windows 10 or Windows 11 (64-bit). Must have an Intel or AMD processor — ARM-based Windows devices (like Surface Pro X) are not supported.

Docker Desktop Req.

Docker Desktop must be installed and running. Download from docker.com. The free tier is sufficient.

Disk Space ~15 GB

Approximately 12 GB for Docker images and 3+ GB for database and application data. An SSD is strongly recommended.

Important: Before running the installer, ensure Docker Desktop is fully started (the whale icon in the system tray is steady, not animating). The installer verifies Docker availability and will fail if Docker is not running.

Step-by-Step Installation

1 Prepare the Installer Folder

Create a folder on the Windows machine (e.g. C:\EyeNet) and copy the three installer files into it:

C:\EyeNet\
├── install-platform.ps1
├── docker-compose.windows-installer.yml
└── .env.windows.template

2 Open PowerShell as Administrator

Right-click the Start button and select "Terminal (Admin)" or "PowerShell (Admin)". If PowerShell's execution policy blocks scripts, first run:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Confirm the prompt with Y when asked.

3 Navigate to the Installer Folder

cd C:\EyeNet

4 Run the Installer

.\install-platform.ps1

The installer will prompt you for three values (only if they're not already in your .env.windows file):

PromptDescription
Installation UUIDYour unique platform installation identifier — obtained from the EyeNet Authority dashboard
Application KeyThe secret application key linked to your installation — also from the Authority dashboard
PostgreSQL PasswordChoose a strong password for the local PostgreSQL database (typed securely, no visible characters)

5 Wait for Pull & Startup

The script will automatically:

  1. Create .env.windows from the template (if it doesn't exist yet)
  2. Pull all 9 Docker images from the public GHCR registry (~2.3 GB total)
  3. Start the full stack with Docker Compose

This may take 5–15 minutes depending on your internet connection speed. You'll see progress bars during the pull.

6 Verify the Installation

docker compose --env-file .env.windows -f docker-compose.windows-installer.yml ps

All 11 services should show Status: Up. If any service shows Restarting or Exited, check the logs:

docker compose --env-file .env.windows -f docker-compose.windows-installer.yml logs

Day-to-Day Operations

Starting and Stopping

All commands must be run from PowerShell (Admin) in the C:\EyeNet folder.

ActionCommand
Start all servicesdocker compose --env-file .env.windows -f docker-compose.windows-installer.yml up -d
Stop all servicesdocker compose --env-file .env.windows -f docker-compose.windows-installer.yml stop
Restart all servicesdocker compose --env-file .env.windows -f docker-compose.windows-installer.yml restart
View service statusdocker compose --env-file .env.windows -f docker-compose.windows-installer.yml ps
View logs (all)docker compose --env-file .env.windows -f docker-compose.windows-installer.yml logs -f
View logs (one service)docker compose --env-file .env.windows -f docker-compose.windows-installer.yml logs -f ppl-meta-node

Updates

To update to a new release:

  1. Stop the stack: docker compose ... stop
  2. Edit .env.windows and change RELEASE_TAG to the new version number
  3. Pull new images: docker compose ... pull
  4. Start again: docker compose ... up -d

Backup

All persistent data is stored in Docker volumes (postgres_data and redis_data). To backup:

  1. Stop the stack
  2. Copy the Docker volumes from Docker Desktop's data directory
  3. Alternatively, use pg_dump against localhost:5433 to export the database

Troubleshooting

Common Issues

IssueSolution
Docker not foundEnsure Docker Desktop is installed and running (check system tray)
"Script not digitally signed"Run Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Port already in useCheck if another app is using ports 3000, 5433, 6379, or 8000–8009. Edit .env.windows to change port assignments
Container keeps restartingCheck logs: docker compose ... logs . Often caused by missing INSTALLATION_UUID or APPLICATION_KEY
Not enough disk spaceFree at least 15 GB. Run Docker Desktop's "Clean up" tool to remove unused images
Cannot pull imagesEnsure internet access. If behind a corporate proxy, configure Docker Desktop's proxy settings
