3. No timestamps → Backend wins (safer for enterprise)

## 🔑 Key Design Decisions

### 1. UUID v4 Generation: Server-Side
**Decision**: Backend generates UUID, not client  
**Rationale**:  
- Security: Prevents client manipulation
- Consistency: Guaranteed unique identifiers
- Pattern match: Same as USB/RTSP cameras

### 2. Hardware Identifier: manufacturer_model_serial
**Decision**: Stable hardware identifier for device detection  
**Rationale**:  
- Survives app reinstalls
- Detects returning devices
- Prevents duplicate registrations

### 3. Pending Settings: PostgreSQL Table
**Decision**: Use PostgreSQL, not Redis  
**Rationale**:  
- Low write frequency (settings infrequent)
- Row-level locking sufficient (no contention)
- ACID guarantees for settings
- Simpler architecture
- Sufficient for expected load (<1,000 cameras)

### 4. Hybrid Architecture: Mobile + Admin
**Decision**: Support both patterns in single codebase  
**Rationale**:  
- B2C customers: Mobile-first (instant, offline-capable)
- Enterprise customers: Admin-driven (policy enforcement)
- Competitive advantage: Most platforms pick one
- Single codebase easier to maintain

### 5. Conflict Resolution: admin_override Flag
**Decision**: Explicit flag for enterprise policies  
**Rationale**:  
- Clear intent (user knows it's a policy)
- Cannot be bypassed by mobile app
- Audit trail for compliance
- Flexible (can be per-setting or per-camera)

### 6. Heartbeat: 30-Second Interval
**Decision**: Polling instead of WebSocket push  
**Rationale**:  
- Simpler implementation
- More reliable (auto-reconnect)
- Battery-friendly (30s not real-time)
- Sufficient for settings updates
- Can upgrade to WebSocket later if needed

## 🔄 Complete Data Flow

### 1. Initial Setup (New User)
```
User opens app
├─> Check for stored UUID → None found
├─> Show Automatic Setup Screen
├─> User clicks "Start Automatic Setup"
├─> App discovers backend (Discovery Service port 8006)
├─> App sends registration request:
│   └─> {manufacturer, model, serial} (NO device_id)
├─> Backend checks hardware_identifier in DB
├─> Not found → Backend generates UUID v4
├─> Backend sends response: {device_id: uuid, name: "auto-generated"}
├─> App stores UUID in SharedPreferences
├─> Start heartbeat service (30s interval)
└─> Navigate to Camera Screen
```

### 2. Returning User (App Reopened)
```
User opens app
├─> Check for stored UUID → Found: "uuid-abc-123"
├─> Auto-authenticate with stored credentials
├─> Start heartbeat service
└─> Navigate to Camera Screen (seamless)
```

### 3. Settings Update (Mobile, Online)
```
User opens Camera Settings
├─> Changes Resolution to "1920x1080"
├─> Clicks "Save Settings"
├─> App saves to SharedPreferences (instant)
├─> App calls PATCH /mobile/{uuid}/settings
├─> Backend checks last_seen → Online (<2 min)
├─> Backend merges with camera.settings JSON
├─> Backend updates last_modified_by = 'mobile'
├─> Backend returns: {applied: "immediately"}
└─> User sees "Settings saved and synced"
```

### 4. Settings Update (Mobile, Offline)
```
User opens Camera Settings (offline)
├─> Changes Frame Rate to 60
├─> Clicks "Save Settings"
├─> App saves to SharedPreferences (instant)
├─> App tries PATCH call → Network error
├─> App adds to offline queue
├─> User sees "Settings saved locally, will sync when online"
├─> [Later] User reconnects to WiFi
├─> App calls offlineQueue.syncAll()
├─> Backend processes queued update
└─> User sees "All settings synced"
```

### 5. Admin Override (Enterprise Policy)
```
Admin opens admin panel
├─> Selects camera "uuid-abc-123"
├─> Changes Storage Limit to 500MB
├─> Sets admin_override = true
├─> Backend checks last_seen → Offline
├─> Backend queues in pending_settings:
│   └─> {admin_override: true, priority: 10}
├─> [Later] Camera sends heartbeat
├─> Backend returns pending_settings in response
├─> Mobile app sees admin_override = true
├─> Mobile app applies setting (no user confirmation)
├─> Mobile app shows: "Policy enforced by admin"
└─> User cannot change this setting
```

## 📝 Migration Plan for Existing Cameras

- No hardware_identifier
- No pending settings table
- No hybrid settings support

### Migration Script: `migrate_mobile_cameras_to_uuid.py`
```python
# What it does:
1. Finds all mobile cameras without hardware_identifier
2. Generates UUID v4 for each camera
3. Stores old device_id in notes field (for reference)
4. Updates device_id with new UUID
5. Generates hardware_identifier from manufacturer+model+serial
6. Initializes default settings JSON
7. Sets last_modified_by = 'system'

# Safety:
- Runs in transaction (rollback on error)
- Dry-run mode available
- Logs all changes
- Preserves original data in notes field
```

### Migration Steps
```bash

# 4. Run actual migration
```
