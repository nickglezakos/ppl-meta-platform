## 🔑 Key Features

### 1. UUID v4 System
- **Server generates** UUID v4 for mobile cameras (not client-provided)
- **Persistent storage** in SharedPreferences (`camera_device_uuid` key)
- **Hardware identifier** (`manufacturer_model_serial`) for device detection
- **Automatic retrieval** on app startup for existing cameras

### 2. Registration Flow
```
Mobile App                          Backend (Cameras Service)
    |                                        |
    |-- POST /mobile/register ---------->   |
    |   {                                    |
    |     manufacturer: "Apple",             |
    |     model: "iPhone 14",                |
    |     serial: "ABC123XYZ"                | → Check hardware_identifier
    |   }                                    |     in database
    |                                        |
    |   <-- 200 OK -----------------------  |
    |   {                                    |
    |     device_id: "uuid-v4-here",    <------- Generated by server
    |     name: "iPhone 14 Camera 1",        |
    |     ...                                |
    |   }                                    |
    |                                        |
    | → Store UUID in SharedPreferences      |
    | → Use UUID for all future API calls    |
```

### 3. Heartbeat System
- **Interval**: 30 seconds (configurable)
- **Purpose**: Maintain online status + apply pending settings
- **Endpoint**: `POST /api/v1/cameras/mobile/{uuid}/heartbeat`
- **Lifecycle**: Auto-start on app foreground, auto-stop on background
- **Response handling**: Apply pending settings from server

### 4. Manual Connection Fallback
- **Trigger**: Automatic discovery/registration failure
- **UI**: Full form with server URL, username, password
- **Navigation**: Accessible from AutomaticSetupScreen
- **Flow**: Direct authentication → Store token → Navigate to camera screen

## 📱 User Experience

### Automatic Flow (Happy Path)
```
1. Open app
2. Check for stored UUID
3. If found → Auto-connect with stored credentials
4. If not found → Show AutomaticSetupScreen
5. Click "Start Automatic Setup"
6. Discovery Service finds backend (port 8006)
7. Register camera (backend generates UUID)
8. Store UUID locally
9. Start heartbeat (30s)
10. Navigate to Camera Screen ✅
```

### Manual Fallback (Error Path)
```
1. Open app
2. Automatic discovery fails
3. Error dialog shows
4. Click "Manual Setup"
5. Enter server URL, username, password
6. Direct authentication
7. Store auth token
8. Navigate to Camera Screen ✅
```

### Pre-emptive Manual (User Choice)
```
1. Open app → AutomaticSetupScreen
2. Click "Use Manual Setup Instead"
3. Skip automatic discovery entirely
4. Enter credentials manually
5. Direct authentication
6. Navigate to Camera Screen ✅
```

## 🔗 Integration Points

### Files Modified

#### 1. `device_identifier_service.dart`
**Added Methods**:
- `storeCameraUuid(String uuid)` - Persist UUID
- `getStoredCameraUuid()` - Retrieve UUID
- `getDeviceSerial()` - Get device serial number

**Usage**:
```dart
// After registration
await DeviceIdentifierService().storeCameraUuid(serverUuid);

// On app startup
final uuid = await DeviceIdentifierService().getStoredCameraUuid();
if (uuid != null) {
  // Use stored UUID for auto-login
}
```

#### 2. `auto_camera_registration_service.dart`
**Key Changes**:
- Remove `device_id` from registration payload
- Send `device_manufacturer`, `device_model`, `device_serial`
- Store server-generated UUID after registration
- Use stored UUID for subsequent calls

**Before**:
```dart
{
  "device_id": "client-generated-id",  // ❌ Client-provided (insecure)
  "device_name": "My Phone"
}
```

**After**:
```dart
{
  "device_manufacturer": "Apple",      // ✅ Hardware components
  "device_model": "iPhone 14",
  "device_serial": "ABC123XYZ"
}
// Backend generates UUID and returns in response
```

#### 3. `mobile_camera_heartbeat_service.dart`
**New Service**:
- Timer-based heartbeat every 30 seconds
- Uses stored UUID for identification
- Applies pending settings from server response
- Auto-manages lifecycle (start/stop)

**Usage**:
```dart
final heartbeat = MobileCameraHeartbeatService();
await heartbeat.startHeartbeat(cameraUuid);  // Start when online
await heartbeat.stopHeartbeat();              // Stop when offline
```

**New Screen**:

- Navigation to camera screen on success

**Accessible From**:

- Error dialog → "Manual Setup" button after failure

#### 5. `automatic_setup_screen.dart`
**Integration Updates**:

## 📝 Notes for Developers

### Backend Expectations
Phase 2 mobile app expects backend to:
1. Generate UUID v4 on camera registration
2. Return UUID in `device_id` field of registration response
3. Accept UUID in all mobile camera endpoints (path parameter: `{uuid}`)
4. Maintain online status based on heartbeat timestamp
5. Queue settings in `pending_settings` when camera offline
6. Return pending settings in heartbeat response for application

### Mobile App Behavior
Phase 2 mobile app:
1. Never generates its own camera UUID
2. Always uses server-provided UUID from registration
3. Stores UUID persistently in SharedPreferences
4. Sends hardware identifier components (not device_id) on registration
5. Sends heartbeat every 30 seconds when in foreground
6. Applies pending settings from heartbeat responses
7. Provides manual connection UI as fallback
